Using Provider Router

Provider Router exposes your selected provider accounts and models through a local OpenAI-compatible API. Applications run their own agent workflows and tools; Router performs model calls only.

Get started

  1. In Providers, add an account using your installed Codex login, direct Codex subscription credentials, or an OpenRouter key.
  2. Refresh models, choose the models and allowed thinking efforts, save, and enable the provider.
  3. Connect your application to the endpoint shown in API access. The default is http://127.0.0.1:47831; OpenAI SDK base URLs end in /v1.

Authentication and network settings

New installations accept local calls without client API keys. API access lets you change the port and require keys. The API keys page creates separate revocable application keys, shown only once. Provider account credentials remain separate. Existing installations retain their authentication requirement after an upgrade.

SDKs that require a nonempty key can use local while authentication is disabled. When keys are required, send Authorization: Bearer YOUR_CLIENT_KEY. Remote access always requires keys and explicit TLS configuration. Browser-origin requests are rejected; use a native application or server client.

Endpoints

GET /health
Public Router identity, protocol version, version, instance ID and whether authentication is required.
GET /v1/providers
Enabled provider connections and their allowed model capabilities, thinking efforts and token limits.
GET /v1/models
OpenAI model list. Each qualified ID is CONNECTION_UUID/MODEL_ID. The provider_router extension includes the connection name, provider, model capabilities and allowed thinking efforts.
POST /v1/chat/completions
OpenAI-compatible messages, tools, structured output and reasoning_effort.
POST /v1/responses
OpenAI-compatible input, function tools, structured output and reasoning.effort. Responses are not stored.
POST /v1/inference
Native protocol request with UUIDv7 request_id, connection_id, model, messages and tools.
POST /v1/inference/REQUEST_UUID/cancel
Cancel an active request owned by the same client. Without keys, local applications share a cancellation identity.

Discover and call a model

Run these commands in a terminal. Replace the endpoint if you changed its port, and add the authorization header when keys are required.

curl http://127.0.0.1:47831/health
curl http://127.0.0.1:47831/v1/providers
curl http://127.0.0.1:47831/v1/models

Copy a qualified model ID from the model list into MODEL_ID below. Choose a thinking effort listed for that model, or omit reasoning_effort to use its configured default.

curl http://127.0.0.1:47831/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"MODEL_ID","messages":[{"role":"user","content":"Reply with hello."}]}'

Behavior and troubleshooting

Streaming is finite SSE emitted after the provider completes. Only text input is supported in protocol version 1. Tool calls are returned to your application for execution. Models and thinking efforts outside your exposed selection are rejected before inference. Closing settings leaves the service running; Quit stops it.

Connection refused: open Router and check API access for its listening endpoint and startup error. HTTP 401: supply a current client key or disable key requirements for local access. HTTP 403: browser-origin requests are unsupported. Unavailable model: refresh the provider catalogue, save your selection and enable the provider. HTTP 429: wait for existing inference requests to finish. Provider authentication failures require repairing the selected provider account.
