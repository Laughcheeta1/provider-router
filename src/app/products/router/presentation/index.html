Connect an application

Use your configured providers through a local OpenAI-compatible API. This guide walks from setup to a working model call. Requests below use a POSIX shell such as Bash, zsh or WSL.

1. Choose a provider and expose models

  1. Open Providers and choose a detected Codex installation, then Use this provider. If login is required, run codex login in that environment. Use Add provider for a custom Codex connection or an OpenRouter API key. Codex calls the subscription API directly using your existing login.
  2. Models load automatically. Select the models and allowed thinking efforts, press Save, then enable the provider. Refresh retries model discovery. GPT-Reserve is excluded from Codex.
  3. Open API access to find your endpoint. Client API keys are optional by default. If Require client API keys is enabled, create a key in the API keys section and copy it when shown; it is displayed only once. Each key can be revoked independently.

2. Set the endpoint and check the service

Use the endpoint shown in API access if you changed the default port. In the same terminal, set:

BASE="http://127.0.0.1:47831"
KEY="local"
# If client keys are required, replace local with your Router client key.

local is a placeholder accepted while key requirements are disabled. Your provider account credentials are never sent by client applications.

curl  "$BASE/health" \
  -H "Authorization: Bearer $KEY"

Example response, HTTP 200:

{
  "name": "provider-router",
  "protocol_version": 1,
  "instance_id": "01a1c8e4-5a20-70fd-a550-f26fa4a5bae4",
  "version": "0.1.0",
  "authentication_required": false
}

The examples use a synthetic provider to show actual Router response shapes. IDs, model names, generated text, timestamps and token counts vary in your installation. No example represents a live provider response.

3. Check readiness and discover models

This check makes no upstream provider call. ready: true means at least one model is exposed; it does not verify the provider login or remaining usage.

Replace that example value with your own model ID. A qualified ID selects the exact account even when several accounts expose the same model. The provider_router metadata lists allowed reasoning efforts, token limits, and support for tools and structured output.

4. Send a Chat Completions request

Read the answer from choices[0].message.content. The model uses its configured default thinking effort when none is supplied.

curl  "$BASE/v1/chat/completions" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  --data @- <<JSON
{
  "model": "$MODEL",
  "messages": [
    {
      "role": "user",
      "content": "Say hello."
    }
  ]
}

6. Request a JSON answer

Choose a model advertising structured_output: true. The content is a JSON string matching your schema. Router validates the answer before returning success.

curl  "$BASE/v1/chat/completions" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  --data @- <<JSON
{
  "model": "$MODEL",
  "messages": [
    {
      "role": "user",
      "content": "What is seven plus seven? Return answer as a number."
    }
  ],
  "response_format": {
    "type": "json_schema",
    "json_schema": {
      "name": "sum",
      "strict": true,

        "type": "object",
        "properties": {
          "answer": {
            "type": "integer"
          }

7. Let your application execute a tool

Choose a model advertising tools: true. Router returns function calls; your application executes them. A tool call does not run code inside Router. Generated arguments and call IDs can differ from this example.

curl  "$BASE/v1/chat/completions" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  --data @- <<JSON
{
  "model": "$MODEL",
  "messages": [
    {
      "role": "user",
      "content": "What is the weather in Bogota?"
    }
  ],
  "tools": [

          "type": "object",

8. Stream a response

Add stream: true and use curl -N to read Server-Sent Events. Router currently waits for provider inference to finish before emitting the stream; streaming does not provide live token-by-token latency.

curl  -N "$BASE/v1/chat/completions" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  --data @- <<JSON
{
  "model": "$MODEL",
  "messages": [
    {
      "role": "user",
      "content": "Say hello."
    }
  ],
  "stream": true
}
JSON

9. Use the OpenAI JavaScript SDK

Install the SDK in your client project with pnpm add openai. Set your actual model ID and, when required, client key:

import OpenAI from 'openai';
const client = new OpenAI({
  baseURL: 'http://127.0.0.1:47831/v1',
  apiKey: process.env.PROVIDER_ROUTER_KEY || 'local',
});
const answer = await client.chat.completions.create({
  model: process.env.PROVIDER_ROUTER_MODEL,
  messages: [{ role: 'user', content: 'Say hello.' }],
});
console.log(answer.choices[0].message.content);
// Example: Hello!

10. Read errors and resolve connection problems

This intentionally requests an unavailable model:

curl  "$BASE/v1/chat/completions" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  --data @- <<JSON
{
  "model": "missing-model",
  "messages": [
    {
      "role": "user",
      "content": "Say hello."
    }
  ]
}
JSON

Actual example error, HTTP 404:

{
  "error": {
    "code": "MODEL_UNAVAILABLE",
    "message": "This model is not exposed by Provider Router.",
    "type": "invalid_request_error",
    "param": null
  }
}
Connection refused
Open Router, check the API access endpoint and startup error, and confirm the port matches your client. Closing settings keeps Router running; Quit stops it.
HTTP 401
Send a current Router client API key, or disable key requirements in API access for local use. Provider keys and Codex credentials are separate.
HTTP 403 in a browser
Add the website’s exact HTTPS origin to Approved website origins in API access, without a path or trailing slash. Use the loopback endpoint and allow local-network access when your browser asks. Native clients do not need origin approval.
No models or unavailable model
In Providers, select a model, Save and enable its provider. Refresh discovery if needed, then copy a current qualified ID from /v1/models.
Invalid thinking effort or unsupported option
Use an effort listed in the model metadata, or omit it for the configured default. Only text input is supported. Images, audio, files, background Responses and stored conversation state are rejected.
HTTP 429 or provider failure
Wait for active requests to finish. For provider authentication failures, repair the selected account login. Router does not switch accounts or providers automatically.

Additional endpoints and limits

Inspect enabled provider connections and their upstream model IDs:

curl  "$BASE/v1/providers" \
  -H "Authorization: Bearer $KEY"
{
  "protocol_version": 1,
  "providers": [
    {
      "id": "019a1111-1111-7111-8111-111111111111",
      "name": "Personal Codex",
      "provider": "codex",
      "method": "codex_http",
      "models": [
        {
          "id": "gpt-example",
          "name": "Example model",
          "reasoning_efforts": [
            "low",
            "high"
          ],
          "default_reasoning_effort": "low",
          "context_window": 32000,
          "max_output_tokens": 4000,
          "tools": true,
          "structured_output": true,
          "input_modalities": [
            "text"
          ]
        }
      ]
    }
  ]
}

POST /v1/inference is the native protocol alternative. It requires UUIDv7 request_id and connection_id, an upstream model ID, messages and tools. Standard OpenAI clients can use the endpoints above.

To cancel by ID, send a UUIDv7 X-Request-ID header on inference and call POST /v1/inference/REQUEST_ID/cancel using the same client key. Success returns {"cancelled":true}. Without required keys, local applications share one cancellation identity.

The API listens only on this computer. Browser access is disabled until an origin is approved. Approve only websites you trust with your provider usage. Output budgets on Codex are checked after completion and do not cap upstream billing or subscription usage.
